# Changes

## 2026-10-01

- Docs: new `OpusDM-Features-Guide.md`, a step by step tour in Italian of every OpusDM feature (setup, Lister, SOURCE/DEST, file operations, search, viewer, terminal, archives, Functions, hotkeys, user menu, script events, desktop, Button Banks, settings), with the keys to press and where to click.

## 2026-09-30

- Button Banks (F-02): free-floating windows of buttons. New `opusdm_ipc::buttonbank` (`ButtonBank`, `Btn`, `Banks`; one file per bank under `~/.config/opusdm/buttons/`, `columns` clamped 1..=32, at most 256 buttons, a file that fails to parse is copied to `.bak` and never overwritten, `create_in_dir` never reuses an id whose file exists, a saved position that is negative or beyond 32000 is dropped) and the new `opusdm-buttonbank` crate: `window.rs` (one window per bank, grid of buttons with icon and label, left / right / middle click each run their own Function, a button whose Functions were all deleted is insensitive with a tooltip, kept out of the taskbar and pager with `_NET_WM_STATE_SKIP_TASKBAR` / `_NET_WM_STATE_SKIP_PAGER`, moved to its saved frame position once the window manager has adopted the window, retried until it sticks; a saved position no connected monitor shows is dropped, and a hidden bank comes back where it was) and `editor.rs` (manager with New, Edit, Delete, Open, Close; editor with preview, Add, Insert, Delete, Copy, Paste, Up, Down, button form and bank appearance). New internal commands `OpenBank`, `CloseBank`, `ToggleBank`, `HideBank` (parameter `bank`, picked from a drop-down of the saved banks in the Function Editor; an unknown bank fails the step with `Bank "<name>" not found`), routed as `FnEvent::Bank` to `HubEvent::Bank`. The hub owns the windows (`crates/hub/src/bank_windows.rs`): banks open when the hub last ran are restored at startup, a click runs the Function through `HubCmd::RunFunctionHeadless`, the position is saved when a window closes and before the hub quits, `Hide` / `Reveal` hide and show the bank windows too. The Function Editor keeps a bank name that no longer exists as "(missing)" instead of rewriting the step. The manager opens from "Button Banks..." in the desktop menu and in the Command Palette (`ToHub::OpenBankManager`).
- Hide and Reveal (F-38): one action hides the environment and leaves the desktop. New internal commands `Hide`, `Reveal` and `Toggle Hide` (no parameters), so a saved function bound to a global hotkey toggles it, and a "Hide All" / "Reveal" button in the desktop menu. The hub owns the state (`hidden`, starts revealed): `ToLister::SetHidden` makes every Lister minimize itself (or restore itself, only if the hub minimized it: `opusdm-lister` `hidden::next_step`), `HubEvent::HiddenChanged` hides the panel, the dock and the group windows (`opusdm_panel::WINDOW_TITLE`, `opusdm_dock::WINDOW_TITLE`). A Lister somebody asked for (`SpawnRequested` / `ToHub::SpawnLister`) opening while hidden reveals everything; the initial one of a `Startup` script is told to hide too (`visible_spawns_pending`). On reveal the Listers restore without raising and the hub presents only the SOURCE Lister, so roles do not shuffle. `opusdm_panel::set_hidden` keeps a panel bar rebuilt on a monitor change hidden.
- Program Groups (F-34): a group is a named collection of programs, files or folders shown as one icon on the desktop. New store `opusdm_ipc::Groups` (`~/.config/opusdm/groups/<id>.json`, one file per group: name, members, optional dragged position; ids are slugs made unique with a numeric suffix, names are unique ignoring case; malformed files are skipped and never deleted). `IconEntry.group` with its own badge and a virtual `group:<id>` path pinned like left-out icons; `opusdm_hub::leftout::DesktopExtras` merges left-out icons and groups into the desktop listing; `launch_action` decides how a member starts (folder in a Lister, `.desktop` application, program with an ELF or `#!` header, default application). `Groups::create_in_dir` never reuses an id whose file already exists on disk, so a malformed group file is not overwritten. New `group_window.rs`: one window per open group with an icon field, double click launches, dropping files adds, context menu "Remove from Group". Desktop: "New Group..." in the desktop menu, dropping files on a group icon adds them, group icon menu with Open, Rename Group... and Delete Group... (members are never touched).
- LeaveOut (F-33): files and folders can be left out on the desktop as permanent icons with an arrow badge. New store `opusdm_ipc::LeftOut` (`~/.config/opusdm/leftout.json`: path plus optional dragged position; duplicates and bad coordinates are cleaned on load), `IconEntry.left_out` and `IconItem` badge, `IconField::set_pinned_positions` / `connect_pinned_moved` (positions kept by path across reloads, only for left-out icons), `scan::entry_for_path`, and `opusdm_hub::leftout::merge_entries` (a path also in the Desktop folder shows once; a missing target stays as a broken icon). Entry points: Lister context menu "Leave Out on Desktop" (`ToHub::LeaveOut`), function steps `Leave Out` and `Put Away` on the SOURCE selection, and "Put Away" in the desktop icon menu. The hub emits `HubEvent::LeftOutAdd` / `LeftOutRemove`; the GTK side owns and saves the store.; `docs/usage.md` 3.12 no longer claims a `.opusdm/` layout directory. Desktop reloads share one latest-wins gate (`opusdm_hub::leftout::ReloadGate`), a reload cancels a drag in progress, a left-out symlink to a folder opens in a lister, and Cut, Rename and Delete are not offered on left-out icons.
- Functions: new internal command "Set Background" (`InternalCmd::SetBackground`, required `path` with placeholders, `~` and cwd-relative paths, optional `fit` = fill / fit / center / tile, empty keeps the current fit). The step checks the file exists and has a png / jpg / jpeg / webp / bmp / gif extension, then the hub sets `theme.background` to that image and applies it through the same path as `ToHub::SetSettings` (now `Hub::apply_settings`): persisted to `settings.json`, live redraw. Hub-originated runs (script events) apply it too. New helpers `ImageFit::parse` and `is_background_image` in `opusdm_ipc::desktop`.
- Lister: right-click an image file, "Set as Desktop Background" (refused for paths containing `{`).
- Docs: `docs/usage.md` section 3.20 describes the Change Directory and Set Background function steps.

## 2026-09-27

- Fix: the dock stayed on top of maximised windows despite `_NET_WM_STATE_BELOW`. Cause: it used `_NET_WM_WINDOW_TYPE_DOCK`, which by EWMH spec tells the window manager to always keep the window raised - the same type the panel uses, for the opposite reason. Switched to `_NET_WM_WINDOW_TYPE_NORMAL` (still undecorated, still no strut) plus `SKIP_TASKBAR`/`SKIP_PAGER` so it stays out of the taskbar and pager; `BELOW` now actually keeps it under normal windows.
- `opusdm-dock` step 5, and the final part of step 4: new `crates/desktop-config/src/dock_ui.rs` with `DockSection` (edge drop-down limited to the edges free of the panel, icon size 32/48/64) and `DockAppsSection` (ordered list of pinned apps with up/down/remove/"Add..." picking a `.desktop` file), reused by a new "Dock" tab in `opusdm-theme`. `PanelSection::connect_position_changed` lets the Panel tab push its edge to the Dock tab live, so the two never offer the same edge. `opusdm-dock` itself gained the rest of step 4: drag-reorder inside the dock (`gtk::DragSource`/`DropTarget` on `String`), dropping a `.desktop` file (or a file list of them) onto the dock to pin it, dragging an icon out to unpin it, and popover context menus (an icon's own `Actions=` entries plus "Remove from Dock"; the background's "Add Application..."). New pure `crates/dock/src/list.rs` (`insert_at`/`remove`) shared by both crates' reordering.
- `docs/dock.md` implementation plan is now a status list: all five steps are done.
- `opusdm-dock` steps 2 and 3 of `docs/dock.md`: the dock now shows the pinned apps from `~/.config/opusdm/dock.json` (new `opusdm_ipc::DockConfig`; a missing file is seeded with file manager, terminal and browser, keeping the installed ones), with the app icon, name tooltip, click-to-launch through `gio::DesktopAppInfo` + the display's launch context, and a short busy cursor. The dock watches `dock.json` with a `gio::FileMonitor` and follows edits live; uninstalled ids are skipped.
- New `opusdm_ipc::DockPosition` (bottom default, top, left, right) with `avoiding(PanelPosition)`, plus `DesktopSettings::dock_position` and `dock_icon_size` (default 48, clamped to `DOCK_ICON_SIZE_RANGE`). The dock never shares the panel's edge (it jumps to the opposite one) and a left/right dock is centered in the strip the panel leaves free (`Placement::rect`).
- `opusdm_dock::attach(app, DockLayout)` returns a setter; the hub spawns the dock next to the panel and calls the setter on `DesktopSettingsChanged`, so edge, icon size and panel edge apply live. The dock follows monitor hotplug.
- New crate `crates/dock` (`opusdm-dock`), step 1 of `docs/dock.md`: a `DOCK`-type window with `_NET_WM_STATE_BELOW` and no strut, so maximised windows cover it. `placement.rs` holds the pure geometry (`DockEdge`, `Placement::rect`, unit-tested; all four edges, default bottom, centered on the primary monitor). `window.rs` applies the X11 hints. `attach(app)` shows a static row of three placeholder themed icons; `main.rs` runs it standalone. Not spawned by the hub yet. The spec now says square corners, since rounding needs transparency.
- New design document `docs/dock.md` for `opusdm-dock`, a launcher-only dock (no strut, opaque, no zoom, no window list, never on the panel's edge). No code yet.
- Removed every Nerd Font dependency: deleted `iconview::glyphs` and `iconview::font_probe`, the "Nerd Font Not Found" startup dialog, the Nerd Font CSS and `scripts/install-font.sh`. Icons now always come from an installed theme; a theme lacking an icon leaves a blank slot. `IconSetId::None` is gone (`IconSetId` is now `Custom(slug)` only, default `breeze-dark`); legacy `"None"`/`"BreezeDark"` values in `settings.json` map to the default. The `breeze-dark` theme is embedded in `opusdm-ipc` and written to `~/.config/opusdm/themes/` by `themes::ensure_default_theme()` whenever it is missing (called by `scan_themes` and the icon loader). `decorate_name` in the Lister lost its glyph parameter.
- Desktop context menu: the "Theme" entry is now called "Settings" (it still launches `opusdm-theme`); the missing-font dialog hint follows.
- New "Panel" setting in the Desktop tab of `opusdm-theme`: choose whether the panel is docked to the top (default) or the bottom of the screen. New `opusdm_ipc::PanelPosition` and `DesktopSettings::panel_position` (`"top"`/`"bottom"` in `desktop.json`; missing field means top), edited through the new `PanelSection` in `crates/desktop-config/src/ui.rs`.
- Panel (`crates/panel`): new `window::Placement` (edge + monitor rect). A bottom bar sits at `mon_y + mon_h - PANEL_HEIGHT` and reserves its space with the bottom slots of `_NET_WM_STRUT_PARTIAL` (including the gap between the monitor and the screen bottom on multi-head setups). `strut_partial` now takes the position.
- The application menu popover opens upwards when the panel is at the bottom (`appmenu::set_direction` flips the `MenuButton` arrow direction).
- `opusdm_panel::attach(app, position)` now returns a setter; the hub calls it on `DesktopSettingsChanged`, so the panel moves live without a restart. Bars are re-docked in place (`redock_bar`) rather than rebuilt, so the primary bar keeps its tray and SNI widgets.
- The desktop icon field keeps its clearance margin on the panel's edge (`keep_clear_of_panel` in `toolbar.rs`): top margin for a top panel, bottom margin for a bottom one.
