# Changes

## 2026-10-05

- Feature (ipc, hub, lister): a hotkey can run a **Bash** command or an **Exec** program as well as a saved Function. The choice is stored in the same `function` field with a prefix (`bash:`, `bash+out:`, `exec:`), so the JSON schema and the protocol are unchanged and old files load as before. New `opusdm_ipc::funcref` (parse, format, quote, `problem`, `to_steps`) turns an inline reference into one synthetic `Run` step, which the hub already executes (no `shlex`: validation splits with the same `cli::tokenize` the Run step uses); `run_function_by_id` resolves it, so global hotkeys work with no Lister open (the command starts in `$HOME`). The validators and `prune` accept runnable inline commands and report the rest on the row (`HotkeyInvalidCommand`, `MenuInvalidCommand`, `ScriptInvalidCommand`). Edit Hotkeys has a Function / Bash / Exec picker (`binding_ui::reference_picker`, with Browse...) and repaints errors in place while you type (`revalidate`); Find Key reports `Runs the command "..."`. The user menu, script events, button banks and file types get the same picker in phase 2.
- Docs: `docs/superpowers/specs/2026-10-05-inline-commands-design.md` specifies bash and exec inline commands wherever a Function can be referenced (hotkeys first). Nothing is implemented.
- Feature (scripts): `scripts/build-release.sh` builds the workspace in release mode and stages the deploy files in `dist/` (git-ignored): `bin/` with the four binaries, `config/` (openbox-rc.xml, picom.conf), `themes/` zips, an `opusdm-session` X11 session script, an `opusdm.desktop` template and `install.sh` (copies dist to a prefix, default `/opt/opusdm`, and registers the xsession).

- Feature (hub, lister): the Hotkey Editor is now a global window like Manage Functions. The Desktop submenu of the desktop context menu has "Edit Hotkeys" right before "Manage Functions"; it launches `opusdm-lister --edit-hotkeys` (`hotkey_editor::open_standalone`), which connects to the hub as a tool client (no Lister registration), reads hotkeys and functions from disk and sends `SetBindings` on Save. The palette's "Edit Hotkeys..." launches the same process (`launch_editor`, built on the new `function_editor::launch_tool`), so the editor no longer lives over a Lister.
- Docs: `docs/WAYLAND-PORT.md` records the Wayland porting exploration (X11 code inventory, what does not port, compositor choice, strategy, estimates). Nothing is implemented.
- Feature (sandbox): `run-x11.sh` starts a compositor (`picom` by default) inside Xephyr, with the new `picom.conf` (XRender backend, the GLX one made GTK4 lose its Vulkan device in Xephyr, shadows, inactive-window transparency, fading). Override with `XEPHYR_COMPOSITOR` (empty disables it) and `XEPHYR_PICOM_CONFIG`; if the compositor is missing the script skips it. Menus and popups get no picom shadow (it was a rectangle that ignored their rounded corners).
- Fix (lister): path bar look-ahead, `Tab` on a suggestion now always stays in the bar and moves the cursor to the end. The suggestion is detected from the selected tail text instead of a length counter that `changed` could reset.
- Feature (lister): look-ahead in the path bar. While you type an absolute local path, the folder that completes the last component is appended as selected text (`/r` shows `/ramdisk/`). `Tab` accepts it, typing on replaces it, `Backspace` removes it and `Enter` ignores it. Hidden folders are suggested only after a leading `.`; bookmarks, remote URLs and archive paths are not completed. Logic in `lister/src/pathcomplete.rs`, wiring in `build.rs` (`wire_path_completion`).
- Fix (hub, ipc): `External` function steps had the same SIGCHLD reaper race as Compress (`child.wait()` could fail with `ECHILD` and report "wait failed" for a command that ran). `poll_exit` moved from `fsops::compress` to `opusdm_ipc::reaped`, with a blocking `reaped::wait`; the External step and Compress both use it.
- Fix (fsops, hub, ipc): Compress failed with "No child processes (os error 10)". The hub's SIGCHLD reaper calls `waitpid(-1)` and collected the compressor before the job could wait for it. The reaper now records every status in `opusdm_ipc::reaped` (last 256), and `compress::poll_exit` recovers the status from there when its own wait gets `ECHILD` (it fails after 2 s without one). Compress also logs to the console with the `[compress:pid]` prefix: the command line and folder, the child pid, its exit status, its stderr and a cancel. The same race can still hit `External` function steps (`hub/src/functions.rs`, `child.wait()`).
- Feature (lister, fsops, ipc, hub): **Compress...** in the file context menu and the Command Palette. A requester asks for the archive name (editable) and the format in a drop-down listing only what the installed tools can write: `.zip`, `.tar.bz2`, `.tar.gz`, `.7z`, `.tar.xz`, `.tar.zst`, and `.gz` / `.bz2` only when one regular file is selected (`CompressFormat::available`, checked against `PATH`). Changing the format swaps the suffix in the name. It acts on the whole selection when it holds the clicked row. New `Op::Compress { archive }` (format from the name suffix) runs as a hub job: `fsops::compress::run_compress` runs `zip` / `tar` / `7z` / `gzip` / `bzip2` in the sources' folder, reports progress from the archive size, kills the tool on cancel, never overwrites an existing archive and removes a partial one. The archive goes to the DEST Lister, or to the current folder when there is none (`link_dialogs::dest_or_cwd`). Sources must share one folder, and a folder cannot be archived into itself.

## 2026-10-03

- Change (hub, lister): a Test from Manage Functions no longer starts in `$HOME` when no Lister is SOURCE. The hub answers `FunctionFailed` with `NO_SOURCE_ERROR` ("There is no SOURCE Lister: select a Lister as SOURCE, then try again."), and the Manage Functions window shows every Test failure in an OpusDM requester as well as in the log.
- Feature (lister, hub): "Manage Functions" is an independent window. It runs as its own process (`opusdm-lister --manage-functions`, `function_editor::open_standalone`; a second launch raises the open window) that links to the hub without registering as a Lister (`Client::connect_tool`), loads the list from `functions.json` and saves with `ToHub::SetFunctions`. The Command Palette entry launches it (`function_editor::launch_manager`), and the Desktop submenu of the desktop context menu has "Manage Functions" right after "Rearrange icons" (`launch_functions_manager`, sharing `spawn_lister_tool` with "Edit File Types"). The Test button shows its output, confirm prompts and copy conflicts in that window; the hub runs a `RunFunction` from such a non-Lister connection with the current SOURCE Lister as SOURCE (`Hub::run_source_for`). The now unused `Ui::function_log` is gone.
- Feature (buttonbank): the bank editor has a **Visible on all desktops** check button. It is saved as `all_desktops` in the bank file (default off, older files still load). When on, the bank window is put on every virtual desktop once mapped (`x11::set_all_desktops`, using `X11::stick_to_all_desktops`); toggling it on an open bank applies at once, and turning it off moves the window to the current desktop only (new `X11::unstick_to_current_desktop`). Verified in the Xephyr sandbox: a bank with the option on stays viewable after `wmctrl -s 2`.
- Fix (hub, panel, dock): the panel bar, the dock and the desktop windows disappeared on every virtual desktop but the first, because openbox put them on the desktop current at map time. New `X11::stick_to_all_desktops` (opusdm-ui) sets `_NET_WM_DESKTOP` to all desktops (`0xFFFFFFFF`) as a property and as an EWMH client message, and sends `_NET_WM_STATE_STICKY`; the panel, dock and desktop windows call it when realized and mapped, and list STICKY in their initial `_NET_WM_STATE`. Verified in the Xephyr sandbox: after `wmctrl -s 2` all three stay viewable.

The new `listview > row` rule in `chrome_css` (meant for drop-down popups) also matched the Lister's `columnview > listview > row` and covered the `file_bg` ground; the listview rules now apply only inside a `popover`.
- Fix (ui): in Light mode the drop-down popups and the radio / check indicators kept the dark Adwaita colours. `chrome_css` only styled `list` (ListBox), but a `gtk::DropDown` popup is a `listview`, and the indicator is a `checkbutton > radio` / `check` child node. Both now use the palette's surface, border and accent colours.
- Feature (hub, lister): the Desktop submenu of the desktop context menu has "Edit File Types" before "Edit Theme". It launches `opusdm-lister --edit-filetypes`, which opens only the File Types editor with no hub connection and no file window (`filetypes_ui::open_standalone`; `open_editor` and the standalone entry share `build_editor`, and `DialogShell::standalone` makes a parentless dialog owned by the application).
- Fix (panel): the SNI tray pinned the hub at ~300% CPU (and dbus-daemon / xdg-desktop-portal with it) after any bus activity. `watch_item` woke on every unfiltered `NameOwnerChanged` and `fetch_item` opened a new session connection each time, which emitted another `NameOwnerChanged`: a feedback loop. Now one shared session connection (`session_conn`), the name watch is filtered to the item's own name (`receive_name_owner_changed_with_args`) and `PropertiesChanged` runs on its own thread (before, it was only read by accident, thanks to the storm).
- Feature (lister): the Find dialog has an **Include binary files (slower)** check button. Off (default) keeps the old behaviour: a file with a NUL in its first 8 KiB is skipped after reading only that head. On, `FindQuery.include_binary` makes `read_for_search` and `scan_text` skip that sniff, so PDFs and other binaries are searched as lossy text (up to 16 MiB each).
- Fix (lister): the Find / Search in Files dialog did nothing when Search, Stop, View or Enter were used. Every handler held only a weak reference to the `Dialog` and nothing owned it once `find_dialog::open` returned, so `upgrade()` always failed. The window's close handler now holds the strong reference, tying the Dialog's life to the window.
- Feature (hub, theme-config): the desktop context menu has "Edit Theme" before "Settings" in the Desktop submenu. It launches `opusdm-settings --edit-theme`, which opens only the Theme Editor, without the Settings window (`build_editor_only`; `editor::open` takes the application and an optional parent; the flag is read in `main`, arguments are not passed to GApplication).
- Fix (lister): the SOURCE / DEST stat bar text now uses the theme's text colour. `chrome_css` sets `label { color }` directly, which beat the colour inherited from `.stat-source` / `.stat-dest`; the rules now also target `> label`.
- Fix (ui): DropDown (Select) labels no longer sit on a darker patch. `chrome_css` only reset `button > *`, so the nested `stack` inside `dropdown > button > box` still got the window colour; all boxes/grids/stacks/frames inside a `button` or `dropdown` are now transparent.
- Fix (lister): Command Palette arrow-key navigation scrolls the selected row into view (`select_and_reveal`). Focus stays in the search entry, so the ListBox never scrolled on its own and the selection could move off-screen.
- Fix (ui): `chrome_css` targeted ListBoxes with `list-box`, which is not a GTK4 CSS node (it is `list`), so every ListBox row kept the theme colour while its inner box got the window colour - a two-tone row (very visible in the Command Palette). Rules now use `list` / `list > row`; a selected row keeps the surface colour with a 1px blue (`#3584e4`) inset border, and the Command Palette rows are more compact (no row padding, 3px vertical margins).
- Refactor (hub): the `HUB_REQUESTER = u64::MAX` sentinel is gone. `JobMeta.requester`, `function_requesters`, `PendingFunctionRun.requester_cid`, `Hub::submit_job`, `start_function_run`, `function_failed` and `JobEngine::submit` take an `Option` (`None` = the hub itself), so every routing site must handle the no-Lister case to compile.
- Refactor (ui, panel, dock, hub): the `[80, 400, 1000]` re-placement delays live in `opusdm_ui::PLACEMENT_RETRY_MS`, and `opusdm_ui::retry_after_map(delays, f)` schedules `f` after each delay; the dock, the panel (map and re-dock) and the hub (panel strut settle, resolution change settle) use it instead of five hand-written timeout loops.
- Refactor (lister): `read_dir_rows` extracts the mtime / uid / gid / mode / size fields once, in `row_fields(&Metadata)`, instead of three copies (live symlink, broken link, plain entry).
- Refactor (logging): the remaining 40 non-test `eprintln!` calls (hub, lister, panel, dock, ui, ipc settings and themes, theme-config) now use `err_log!`, so they carry the same `[tag:pid]` prefix as the rest. `err_log!` takes an expression as its tag (`settings::read_json` passes its `app_tag`) and can be used in expression position. Test-only `eprintln!` (skipped-test notes) stay.
- Perf (lister): an auto-refresh of the folder already on screen no longer replaces the whole list. `apply_navigation` keeps the store in name order and `replace_changed_rows` splices only the span that differs (`model::changed_range`), so unchanged rows are not rebound, the scroll position stays and the keyboard cursor keeps its row (clamped to the new length). Opening another folder still replaces everything and resets the cursor. `Row` derives `PartialEq`.
- Fix (iconview): `IconEntry` carries `modified` (whole seconds since the epoch). `refresh_entries` keeps a cached thumbnail only when the entry's path and `modified` are unchanged (`thumbnail_still_valid`), so an overwritten image gets a new thumbnail on the next refresh instead of keeping the old one until the folder is reopened. The cache is still re-keyed by index; keying it by `(path, mtime)` outright was left for later.
- Refactor (hub): Function step dispatch is one exhaustive `match` on `InternalCmd` in `run_steps_cancellable`; the seven `unreachable!` arms of `run_internal` are gone. `run_internal` is split into `run_rename`, `run_make_entry` and `run_file_job` (with a small `FileJob` enum), so adding an `InternalCmd` no longer compiles until it is dispatched.
- Refactor (hub): `Hub::submit_job(requester, spec, waiter)` is the single place that submits to the job engine and records the `JobMeta`; `lister_run_job`, `HubCmd::RunJob` and `function_job` use it instead of three copies.
- Refactor (hub): one `broadcast(conns, &msg)` / `Hub::broadcast(msg)` replaces the nine copies of the "send to every registered Lister" loop (settings, bindings, formats, functions, invalidate, free caches, hidden, shutdown, job done), and `roles_msg(roles)` builds the `RoleChanged` message once for the broadcast and the reject paths of `apply_role`. (Wrapping `Bindings` / `FormatStore` in `Arc` was left out: it changes the wire types.)
- Refactor (lister): three more groups leave the `Ui` struct, like `ViewState` / `StatusBar` / `NavHistory` before them: `FormatState` (`format_state.current`, `format_state.temp`), `Caches` (`caches.dirs`, `caches.sizes`, `Caches::clear`) and `Typeahead` (`typeahead.buffer`, `typeahead.timer`). `Ui` loses six fields; no behaviour change.
- Refactor (lister): `build::build_window` (~630 lines) is split into `build_stat_bar`, `build_file_view`, `wire_filter_bar`, `build_terminal_pane`, `build_message_row`, `build_nav_bar`, `start_watcher`, `assemble_ui` and the `wire_*` functions (`wire_stat_bar`, `wire_navigation`, `wire_selection`, `wire_window_signals`, `wire_keys`, `wire_icon_view`). `build_window` itself is a ~70-line sequence of those steps. No behaviour change; smoke tested by running the hub with its first Lister, panel and dock in Xephyr.
- Perf (panel): the system tray thread no longer wakes up 60 times a second. It sleeps in `poll(2)` on the X connection and an eventfd; the new `systray::TraySender` (returned by `systray::spawn`, used by the tray widget) writes the eventfd after queueing a `TrayCmd`. An idle desktop wakes the thread zero times.
- Refactor (X11): one lazily opened connection per process for window manager requests. New `opusdm_ui::with_x11` / `X11` (atoms interned once, `pin_geometry`, `configure`, `move_resize`, `add_wm_states`, `raise_above`, `send_to_root`); it waits for a round trip when the closure returns and reconnects after an error. The dock, the hub desktop window, the panel (window hints, raise, click actions) and the button banks use it instead of ~20 `x11rb::connect` calls, so a window map no longer opens several connections. The long-lived connections (tray, EWMH observer, screen watcher, global keys) are unchanged. `x11::tests::shared_connection_interns_once_and_moves_a_window` (ignored, needs `DISPLAY`) checks it against a live server.
- Refactor (hub, lister, buttonbank): the hub now owns the Functions, like the bindings. New `ToHub::SetFunctions`, `ToLister::FunctionsUpdate`, `Welcome.functions` and `HubEvent::FunctionsChanged`; the hub keeps `current_functions` (loaded once, written by the persist thread). Listers keep a copy in `HubConnection.functions` instead of reading `functions.json` on every right-click, palette open, hotkey key press and bank button check; the Function Editor saves on top of the hub's latest list (`upsert_function`, `delete_function`), so two Listers no longer overwrite each other's file. The hub's bank windows and bank editor read the same copy (`Hooks.functions`); `palette::get_commands` takes the function list.
- Fix (hub): Function steps Copy, Move, Delete, Copy As, Move As and Duplicate now run on the hub's `JobEngine` (new `FnEvent::Job`, `Hub::function_job`; `FnEvent::Conflict` and `function_conflict` are gone). They get the progress window and cancel button, the standard conflict prompt and the `InvalidatePath` refresh of the open Listers. Each run has a `CancelToken` (`function_cancels`): when its Lister closes, the run stops before its next step and its jobs are cancelled. A conflict nobody can answer is skipped (hub jobs included) and `conflict_owners` covers every prompt. A cancelled job fails its step. Shutdown hooks run such jobs in place with `functions::run_job_inline`.
- Perf (lister): `select_names` matches rows against a `HashSet` and applies them with one `set_selection` call, so restoring a large selection after a reload fires `selection-changed` (status line, preview) once instead of once per row.
- Fix (lister): auto-refresh no longer clears the filter being typed. `apply_navigation` resets the filter bar only when the folder changes, so `on_directory_changed` is a plain `reload()` (the save and restore of the filter text, which raced with the asynchronous listing, is gone).
- Fix (lister): the rename dialogs (button, command, context menu) build the target from the renamed file's own folder (`actions::renamed_sibling`, `rename_and_reload`) instead of the Lister's current folder when OK is pressed, and reject empty names, `.`, `..` and names containing `/`.
- Fix (rename): new `opusdm_fsops::rename_noreplace` (`renameat2(RENAME_NOREPLACE)`, with a check-then-rename fallback) replaces `std::fs::rename` at all 7 call sites (Lister rename dialog, command, context menu, icon view, batch rename, Function Rename step, desktop rename), so a rename never overwrites an existing file. Batch rename (`rename_all`) goes through temporary names, so chains such as `a -> b, b -> c` are order independent and a clashing entry is restored and reported.
- Fix (fsops): an overwriting `copy_file` writes a hidden temp file next to the destination and renames it over the target only after success. A cancel, a full disk or a read error now keeps the old file and removes the temp file.
- Fix (fsops, hub): `copy_file` compares `(dev, ino)` of source and destination before opening for overwrite and refuses with `InvalidInput`, so a DEST reached through a symlink or bind mount can no longer truncate the source. Function steps (Copy, Move, Delete, ...) now run `validate_op` like the job engine does.
- Fix (hub): connection ids only ever grow (`free_conns` is gone), so a stale `ListerEof` / `FromLister` from a dead reader thread can no longer hit a Lister that connected later.
- Docs: new `OPTIMIZE.md`, a prioritised list of 22 code review findings (connection id reuse in the hub, copy / rename data-loss risks, Lister refresh issues, duplicated X11 helpers, and so on).
- Fix (dock): the dock now sits on the configured edge. openbox ignored the position of the plain `ConfigureWindow` the dock sent, so the dock stayed where the `Smart` placement put it (top left, or the middle of the screen with `<center>yes</center>`); `window::pin_geometry` now also sends `_NET_MOVERESIZE_WINDOW`, like the hub desktop window. The X connections used for the dock hints now wait for a round trip (`window::sync`) before closing: closing right after a flush lost the `_NET_WM_STATE` messages, so the dock was never BELOW, SKIP_TASKBAR or SKIP_PAGER. The states are re-sent with the delayed pins after map, once openbox has adopted the window. The dock size counts the stylesheet border (`placement::BORDER`), so the geometry matches the size GTK insists on.
- Fix (panel): the taskbar leaves out windows with `_NET_WM_STATE_SKIP_TASKBAR` (the dock, the button banks).
- Fix (X11): new `opusdm_ui::x11_sync` (a round trip before a short-lived `x11rb` connection is dropped), used by every function that opens a connection, sends window manager requests and closes it: the dock (`window.rs`, replaces its local `sync`), the hub desktop window (`desktop.rs`), the panel (`window.rs`: geometry, hints, raise above; `ewmh.rs`: click actions) and the button banks (`x11.rs`: skip taskbar, move). Long-lived connections (tray, EWMH observer, screen watcher) are unchanged.
- Feature: the theme is the single source of the look. Colours, appearance (type indicators, monospace list, themed window), fonts and the Lister / requester pictures are edited only in the Theme Editor; the Settings window keeps only preferences (active theme, light / dark, wallpaper, icon grid, desktop folder, panel, dock, menu, behaviour). Spec and plan: `docs/superpowers/specs/2026-10-02-theme-single-source-design.md`, `docs/superpowers/plans/2026-10-02-theme-single-source.md`.
- Applying a theme is no longer a partial merge: `apply::resolve_look` (replaces `merge_custom_theme`) gives the theme's values and the defaults for the parts it does not set, and copies light / dark, behaviour and the desktop background from the preferences. `model::resolve_selected` replaces `apply_icon_set`; a theme never touches `DesktopSettings` any more. `settings.json` keeps the resolved look as the runtime cache (the hub is unchanged).
- `theme.json` drops the `behavior`, `desktop` and `background` sections (old files still parse, the values are ignored); `appearance.theme_mode` in a theme is ignored. `ThemeDraft` loses the same fields; `ThemeDesktopMetrics` is gone.
- Wallpapers in a theme: new `wallpapers/` folder (`themes::WALLPAPERS_DIR`), `themes::theme_wallpapers` (sorted pictures plus the picture a legacy `background.image` names, `themes::legacy_wallpaper`), `AssetOp::AddWallpaper` / `RemoveWallpaper`, `draft::queue_remove_wallpaper`. The writer carries `wallpapers/` and copies a legacy desktop picture into it; Import keeps only pictures in it. The Theme Editor Pictures tab shows a WALLPAPERS list instead of DESKTOP BACKGROUND.
- Settings window: "From theme..." next to "Browse..." in BACKGROUND (`BackgroundSection::connect_theme_pictures`, a thumbnail chooser of the selected theme's wallpapers). The Lister tab keeps only BEHAVIOUR (PRESET, COLOURS and APPEARANCE moved to the Theme Editor); "Save theme..." is removed (Duplicate / Save as copy in the editor cover it); the picker is headed THEME and the light / dark selector LIGHT / DARK; "Edit theme..." is now "Edit themes...".
- Theme Editor: the Colours tab no longer offers light / dark; the default theme (`breeze-dark`) is read only (`writer::is_read_only`, `write_theme` refuses it, the editor says to duplicate it).
- Migration: `Settings.look_version` (`CURRENT_LOOK_VERSION` = 1, missing reads 0). On start `opusdm-settings` runs `migrate::migrate_look`: when the look in an older `settings.json` differs from the active theme it is saved as a new theme "My Theme" (`my-theme`, `my-theme-2`, ...; pictures that no longer exist are dropped) carrying the active theme's icons, fonts, sounds and wallpapers, and selected; the result is persisted through `apply_full` and reported in the note line.
