# Changes

## 2026-10-11
- Feature (viewer): `opusdm-viewer` shows PDF documents. Pages are rendered with `hayro` 0.8 (pure Rust, Apache-2.0/MIT, no system library; it needs Rust 1.92, so the workspace `rust-version` goes from 1.91 to 1.92). New `MediaKind::Pdf` (extension `pdf`), so PDF files join the gallery of the folder. New `crates/viewer/src/pdf.rs`: `open`, `render_page` (white background, 2 px per point = 144 dpi, longest edge capped at 8192 px), `render_thumb` (first page, for the strip) and a page worker thread that keeps the last opened document and renders only the newest request. A page is a `RawImage`, so zoom, drag, rotation and the sharp-pixel switch work as for pictures. Keys (PDF only): **Page Down** / **Page Up** next / previous page, **Home** / **End** first / last page (`keys::page_after`); zoom and rotation stay across pages (`ImageView::replace_image`) and the view goes back to the top. Info bar shows `page 2/10`. Slideshow shows a PDF for 4 seconds like a picture. New default file type **PDF file** (`*.pdf`, double click `exec:opusdm-viewer {f}`); existing `filetypes.json` files are not changed. Limits: no text selection or search, no links, password protected files unsupported, zooming past the 144 dpi render gets soft. 10 new unit tests (rendering, missing page, damaged file, thumbnail size, scale cap, worker, page keys, page moves, default PDF type), plus PDF cases in the kind, slideshow and file type tests. Checked: 25 real PDFs from `~/Downloads` (1 to 791 pages, up to 6.5 MB) all rendered, first page in 2 to 95 ms in release except one image-heavy file (677 ms); the only all-white page is blank in `pdftoppm` too; the debug binary starts on a real PDF without errors. NOT checked by eye: the window with a PDF (page keys, info bar, thumbnails).
- Change (Lister): the button row starts with a **Parent Directory** button (up arrow, same as the navigation bar one), before Copy; it calls `commands::go_parent`, so archives and remote folders work as with the nav bar button.
- Change (Theme Editor): the editor opens on the active theme (`settings.json` `theme.icon_set`; the first theme when it is not installed), also after Delete. The default theme, which cannot be changed, no longer shows its tabs: the right side shows only a message pointing to Duplicate / Save as copy, and Save, Revert, Save & Apply and Delete are disabled. The theme open in the editor is previewed live on the running desktop: a 250 ms timer resolves the widgets' draft (`apply::resolve_draft`, pictures taken as the draft's absolute paths) and sends it to the hub with `SetSettings` when it changed (`model::send_preview`, nothing is written when no hub runs). Closing the editor sends back the settings in force when it opened; Save of the active theme and Save & Apply move that baseline to the saved look, Save of another theme does not. `apply_theme` takes the baseline as preferences instead of re-reading `settings.json`, which now holds the preview. Note: the hub persists every `SetSettings`, so if the editor crashes the preview stays in `settings.json`. 1 unit test. Checked in Xephyr with a fake hub on the socket: the active theme "My Theme" selected at open; the default theme shows the message; toggling Type indicators sent a preview, Close + discard sent the original settings back; selecting Breeze Dark previewed it and Close restored "My Theme". NOT checked: Save and Save & Apply against a real hub, the Lister repainting.
- Feature (polkit): new `opusdm-polkit`, a polkit authentication agent (crate `crates/polkit`, spec `docs/superpowers/specs/2026-10-11-polkit-agent-design.md`). Before, `pkexec` programs such as Synaptic started from `opusdm-run` or the menu failed silently: no agent was registered for the session, so polkitd refused without asking for a password. The agent registers on the system bus for the login session (`XDG_SESSION_ID`, logind fallback), serves `org.freedesktop.PolicyKit1.AuthenticationAgent` (only polkitd may call it) and shows one GTK dialog per request: icon, message, user choice (group identities expanded to their members, current user first), the PAM prompt, errors, details; a wrong password starts a new run of `polkit-agent-helper-1` and keeps the dialog open; `CancelAuthentication` closes it. Wayland: centered overlay layer surface with exclusive keyboard; X11: centered on the primary monitor, kept above. The hub starts it at login (a second instance exits through GApplication uniqueness); `build-release.sh` ships it and `live-update.sh --all` restarts it. 13 unit tests (helper protocol and `g_strcompress` unescaping, a fake helper for success, failure and a helper that dies, identity expansion and ordering, centering). Checked: the debug binary registers with the real polkitd 126 and stays up. NOT checked: a real password dialog end to end (`pkexec`, Synaptic), Wayland.
- Feature (panel): the battery tray reads the screen brightness again every time its popover opens, so the slider follows changes made by keys or other programs. `opusdm-brightness`: the worker takes a read command besides set (`Controller::read`) and answers with the new `Event::Current`; a burst of commands applies the last set, then reads once. Checked: unit tests; in Xephyr, brightness changed to 50% through logind with the panel running, the reopened popover showed 50% (then set back to 30%).
- Feature (panel): battery tray next to the device, audio and network trays, in the spirit of the KDE Plasma battery applet. The icon is a battery filled to its level (red at 15% or less when unplugged) with a bolt over it on mains power; the tooltip gives level, state and time left. The popover shows level and state (Charging, Discharging, Fully charged, "Plugged in, not charging"), a level bar, time until empty or full, battery health (UPower `Capacity`), the power profile (Power Save / Balanced / Performance through power-profiles-daemon, hidden without it) and a display brightness slider (the `opusdm-brightness` worker, started only once a battery is found; hidden when no method works). The tray is hidden on machines without a battery. New crate `opusdm-power` (UPower and power-profiles-daemon over the system bus, no GTK, with a `power_state` example); `opusdm-watch` gains `signal_ticks_any` to wake on signals from several bus names. Checked: unit tests; `power_state` example against the real UPower; in Xephyr the icon shows, the popover lists 93% / Fully charged / health 73% / profiles / brightness, and a click on Power Save switched the real profile (then set back to Balanced). NOT checked live: the discharging and charging states (laptop stayed plugged in and full), and that the brightness slider follows changes made elsewhere (it does not: it shows the value read at start and the user's own moves).
- Fix (scripts): `dist/install.sh` run while OpusDM is running from the prefix stopped at `cp: cannot create regular file '/opt/opusdm/bin/opusdm-hub': Text file busy` (`set -e`), before registering any session, so no OpusDM entry appeared in SDDM. Binaries and session scripts are now copied as `<name>.new` and renamed over the old file (`install` + `mv -f`, as `live-update.sh` does); running processes keep the old file. Checked: `cp` over a running test binary fails with "Text file busy" while `install` + `mv` succeeds; dry run with a fake `sudo` writes `opusdm-wayfire.desktop` and `opusdm-labwc.desktop`. NOT checked: the real install.
- Change (scripts, Wayland): `dist/install.sh --wayland` now takes the compositor, `--wayland labwc` or `--wayland wayfire` (given twice, both are registered). Before copying anything it stops when the chosen compositor is not installed (`command -v`), instead of only warning. Each compositor gets its own login entry, `/usr/share/wayland-sessions/opusdm-<compositor>.desktop`, named **OpusDM (labwc)** or **OpusDM (wayfire)**; the old single `opusdm-wayland.desktop` entry is removed. The entry template has a `@COMPOSITOR@` placeholder and its `Exec` passes the compositor to `opusdm-session-wayland`, which now takes `labwc|wayfire` as its argument (rejects any other, exit 2); without it the old choice stays (`OPUSDM_COMPOSITOR`, else Wayfire when installed, else labwc). Checked: `sh -n` on the generated scripts; `install.sh` with no session, `--wayland` with no value, `--wayland sway`, and a compositor missing from `PATH` all stop before installing; the entry generated for labwc; the session script with a fake `labwc`/`wayfire` runs the right one for each argument and the old choice without one. NOT checked: a real install and login from SDDM.
