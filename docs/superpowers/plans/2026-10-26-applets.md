# Applets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner drop a folder with `applet.json` and `main.js` into `~/.config/opusdm/applets/` and get a JavaScript applet (GTK widgets, canvas, network) on the X11 desktop, moved with Alt + drag or the edit mode, managed from `opusdm-applet-browser`.

**Architecture:** A new process `opusdm-applets` (started and supervised by the hub) runs one Boa `Context` per applet on its own GTK main loop, so a bad applet cannot touch the hub. A new crate `opusdm-jscore` holds the code shared with the Lister scripts (`opus.http`). `opusdm-applet-browser` and `opusdm-settings` talk to the applet process over its own Unix socket, never through the Lister protocol.

**Tech Stack:** Rust 2021 (workspace, rust-version 1.92), gtk4 0.10, boa_engine 0.22 (as in `crates/hub`), cairo (through gtk4), serde/serde_json, `ureq` with native-tls for HTTP (see Task 1), x11rb through `opusdm_x11` / `opusdm_ui::with_x11`.

**Spec:** `docs/superpowers/specs/2026-10-26-applets-design.md`. Phase 5 of the spec (bridge to the hub: `opus.command`, `opus.listers`, `opus.runFunction`) is NOT in this plan; it gets its own plan after Task 16 works.

## Global Constraints

- Applet folder: `~/.config/opusdm/applets/<id>/` (`opusdm_ipc::settings::config_dir().join("applets")`); `<id>` is the folder name; the manifest has no `id` field.
- Applet state: `opusdm_ipc::settings::state_dir().join("applets").join("<id>.json")`; never write inside the applet folder.
- Manifest file `applet.json`, script `main.js` (default `entry`), resources anywhere inside the folder.
- X11 only; the Wayland code paths must not change behaviour.
- No bridge to the Listers: no `opus.command`, `opus.listers`, `opus.runFunction`, `opus.lister` in applets.
- `permissions` (`net`, `fs`, `exec`) are parsed and shown, never enforced.
- Applet process: one process, one Boa `Context` per applet, started by the hub; a hung applet may stall the other applets but never the hub.
- `opus.http` HTTPS required; weather source Open-Meteo (no API key); HTTP client dependency kept small and reusing the TLS stack already linked (`native-tls`).
- Every failure path logs with `opusdm_ipc::err_log!` and the applet window shows the error; no silent early return (`CLAUDE.md` rule 3).
- `CLAUDE.md` rules 1-8 apply. Rule 2: the commit body of Tasks 14 and 16 (and any commit that adds a `Weak`/`Rc` cycle, a thread or a worker) answers "who owns this object for the whole run, and what happens when it is gone?". Rule 4: after Tasks 2, 8a, 14 and 16 (the tasks that touch the hub) run the checklist (Lister: Enter in the path bar, double click on a folder, Backspace / parent, Alt+Left/Right, F-keys; hotkeys: Ctrl+backslash, Ctrl+Shift+space, Ctrl+Print, Alt+1 / Alt+2; hub: second Lister, SOURCE/DEST, a Copy job, a function run) in the X11 sandbox (`run-x11.sh`) and, with the owner, in the running session (`scripts/live-update.sh --all`, needs sudo). Say plainly in `CHANGES.md` what was not checked.
- Xephyr sandbox limits (see memory): Alt/Ctrl+backslash do nothing in `run-x11.sh`; notifications reach the real session; kill processes by PID, process names are cut at 15 characters (`opusdm-applet-b`).
- Code and comments in English, `-` and never the long dash; every function and method has a comment, public ones have a doc comment (`///`, JSDoc in `.js`); exit conditions at the top as one liners (`if !foo { return; }`); constants in UPPER_CASE; text files end with an empty line.
- `CHANGES.md` gets an entry for every task that changes the repository (what was NOT verified too). Commit only the files you changed, one risky change per commit, never push, never `--no-verify`, no AI attribution lines in commit messages.

## Review Focus

Failure modes the spec implies but a plain task test would not cover; each has its test in the task named.

1. An applet folder with a missing or broken `applet.json` (bad JSON, no `name`, `entry` pointing outside the folder) must be listed with its error and must not stop the other applets (Tasks 3, 4, 8).
2. The network fails: unreachable host, silent server, 404, redirect loop, body larger than the cap, a non-UTF-8 body. A 404 is a response, the rest is an error with a message (Task 1).
3. A callback of an applet throws, a promise rejects unhandled, or a timer callback loops forever: the window shows the error, the log has it, the process and the other applets live on (Task 5).
4. A saved position is off screen after a resolution change or a monitor unplugged: the applet comes back inside a monitor (Task 11).
5. Two `opusdm-applets` processes (the hub is restarted while the old one lives): the second exits at once with `EXIT_ALREADY_RUNNING` and logs; the supervisor does not count that as a restart, so when the old process dies the new hub still brings the applets back; the edit-mode flag and the enabled list stay consistent (Tasks 8b, 14).

### Task 8b: the applets protocol, the socket and the single instance

No GTK in this task.

**Files:**
- Create: `crates/applets/src/protocol.rs`, `crates/applets/src/instance.rs`
- Modify: `crates/applets/src/main.rs`, `crates/applets/src/lib.rs`, `crates/applets/Cargo.toml`

**Interfaces:**
- Produces `protocol` (framing with `opusdm_ipc::frame::{send, recv}`):
  - `pub enum Request { List, SetEnabled { id: String, enabled: bool }, Reload { id: String }, SetEdit(bool), GetEdit }`
  - `pub enum Reply { Applets(Vec<AppletStatus>), Edit(bool), Ok, Error(String) }`
  - `pub struct AppletStatus { pub id: String, pub name: Option<String>, pub description: String, pub version: String, pub enabled: bool, pub running: bool, pub error: Option<String> }`
  - `pub const ENV_SOCK: &str = "OPUSDM_APPLETS_SOCK"`, `pub fn socket_path() -> PathBuf` (env override, else `hub_sock_path()` parent joined with `applets.sock`), `pub fn request(req: &Request) -> std::io::Result<Reply>` (client helper, connect and read timeout 1 s)
- Produces `instance::acquire() -> Result<UnixListener, Exit>`: `opusdm_ipc::instance::acquire_socket(socket_path(), probe)` where `probe` sends `Request::GetEdit` and expects a `Reply::Edit`.
