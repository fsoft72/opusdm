# LeaveOut (F-33) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user leave files and folders out on the desktop as permanent icons with an arrow badge, remembered (with the position they were dragged to) across restarts, and put them away again.

**Architecture:** A pure store `LeftOut` (`leftout.json`, crate `ipc`) is owned by the hub's GTK side. The desktop `IconField` gets an `IconEntry.left_out` flag (badge overlay) and per-path pinned positions that survive `set_entries` / `refresh_entries`. The hub merges the Desktop folder listing with the store (`opusdm_hub::leftout::merge_entries`) at every place that fills the field. Lister menu, `ToHub::LeaveOut`, and the new `LeaveOut` / `PutAway` function steps all end in `HubEvent::LeftOutAdd` / `LeftOutRemove`, which the GTK side applies to the store.

**Tech Stack:** Rust workspace (crates `ipc`, `iconview`, `hub`, `lister`), GTK4, serde. Tests with `cargo test`; `DISPLAY` is available here, so the single GTK test in `iconview` really runs.

**Spec:** `docs/superpowers/specs/2026-09-30-leaveout-design.md`

## Global Constraints

- Store file: `~/.config/opusdm/leftout.json`, shape `{"items":[{"path":"/etc/fstab","x":120.0,"y":80.0}]}`, `x` and `y` optional.
- Positions are stored per path, only for left-out icons. Desktop folder icons stay auto-slotted.
- A left-out path that also lives in the Desktop folder appears once, with the badge.
- A left-out path that no longer exists stays visible as `IconKind::Broken` and is removed only by Put Away.
- Menu texts: "Leave Out on Desktop" (Lister), "Put Away" (desktop icon menu). Command labels: "Leave Out", "Put Away", no parameters.
- Error messages: `Leave Out: nothing selected`, `Put Away: nothing selected`, `Leave Out: <path> is not an absolute path`, `Leave Out: <path> does not exist`.
- English only in code and comments; never use the long dash character; constants in UPPER_CASE; every function gets a doc comment; text files end with an empty line.
- Commit after each task, meaningful message, no AI attribution lines, never `--no-verify`, do not push.
- Final checks: `cargo build --all`, `cargo test --all`, `cargo clippy --all` (no new warnings in touched code). `iconview`'s `thumbs::cache` test is flaky under parallel load; rerun it alone before calling it a failure.

## Review Focus

- A path both in the Desktop folder and in the store shows one icon, flagged (Task 4 test).
- A missing target becomes a `Broken` flagged entry and stays in the store (Task 4 test, Task 1 test).
- NaN, infinite or negative coordinates in `leftout.json` lose the position, not the item (Task 1 test).
- Leaving out the same path twice, or putting away a path that is not left out, changes nothing (Task 1 tests).
- A nonexistent or archive-virtual path sent from the Lister is refused with a message and nothing is stored (Task 3 server test, Task 6 flash).

```rust
//! Icons "left out" on the desktop: permanent shortcuts to any file or folder,
//! stored in `~/.config/opusdm/leftout.json`. See
//! `docs/superpowers/specs/2026-09-30-leaveout-design.md`.

use serde::{Deserialize, Serialize};
use std::collections::{HashMap, HashSet};
use std::io;
use std::path::{Path, PathBuf};

/// File name of the store under the OpusDM config directory.
pub const LEFTOUT_FILE: &str = "leftout.json";

/// Path of `leftout.json` under the OpusDM config directory.
pub fn leftout_path() -> PathBuf {
    crate::settings::config_dir().join(LEFTOUT_FILE)
}

/// One left-out entry: the target path and, once the user dragged it, where
/// the icon sits on the desktop.
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct LeftOutItem {
    pub path: PathBuf,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub x: Option<f64>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub y: Option<f64>,
}

/// The whole set of left-out icons, in the order they were left out.
#[derive(Debug, Clone, PartialEq, Default, Serialize, Deserialize)]
#[serde(default)]
pub struct LeftOut {
    pub items: Vec<LeftOutItem>,
}

/// Whether `v` is a usable icon coordinate: finite and not negative.
fn coordinate_ok(v: f64) -> bool {
    v.is_finite() && v >= 0.0
}

impl LeftOut {
    /// Append every path not already present, keeping the existing order.
    pub fn add(&mut self, paths: &[PathBuf]) {
        for path in paths {
            if self.items.iter().any(|i| &i.path == path) {
                continue;
            }
            self.items.push(LeftOutItem { path: path.clone(), x: None, y: None });
        }
    }

    /// Drop every item whose path is in `paths`. Unknown paths are ignored.
    pub fn remove(&mut self, paths: &[PathBuf]) {
        self.items.retain(|i| !paths.contains(&i.path));
    }

    /// Record where the icon of `path` sits. Unknown paths are ignored.
    pub fn set_position(&mut self, path: &Path, x: f64, y: f64) {
        let Some(item) = self.items.iter_mut().find(|i| i.path == path) else { return };
        item.x = Some(x);
        item.y = Some(y);
    }

    /// The saved position of every item that has both coordinates.
    pub fn positions(&self) -> HashMap<PathBuf, (f64, f64)> {
        self.items
            .iter()
            .filter_map(|i| Some((i.path.clone(), (i.x?, i.y?))))
            .collect()
    }

    /// Drop duplicate paths (first wins) and clear the position of any item
    /// whose coordinates are not finite and non-negative. Items are never
    /// dropped for a bad position.
    pub fn sanitized(mut self) -> LeftOut {
        let mut seen = HashSet::new();
        self.items.retain(|i| seen.insert(i.path.clone()));
        for item in &mut self.items {
            let ok = matches!((item.x, item.y), (Some(x), Some(y)) if coordinate_ok(x) && coordinate_ok(y));
            if !ok {
                item.x = None;
                item.y = None;
            }
        }
        self
    }

    /// Load from `path`: missing or malformed gives an empty store, then
    /// [`LeftOut::sanitized`].
    pub fn load_from(path: &Path) -> LeftOut {
        crate::settings::load_json::<LeftOut>(path, "opusdm", "left-out icons").sanitized()
    }

    /// Save to `path`, creating the parent directory.
    pub fn save_to(&self, path: &Path) -> io::Result<()> {
        crate::settings::save_json(path, self)
    }

    /// [`LeftOut::load_from`] the standard path.
    pub fn load() -> LeftOut {
        LeftOut::load_from(&leftout_path())
    }

    /// [`LeftOut::save_to`] the standard path.
    pub fn save(&self) -> io::Result<()> {
        self.save_to(&leftout_path())
    }
}

/// Check that every path can be left out: absolute, and present on disk (a
/// dangling symlink counts as present). The error names the first offender.
pub fn check_leavable(paths: &[PathBuf]) -> Result<(), String> {
    for path in paths {
        if !path.is_absolute() {
            return Err(format!("Leave Out: {} is not an absolute path", path.display()));
        }
        if std::fs::symlink_metadata(path).is_err() {
            return Err(format!("Leave Out: {} does not exist", path.display()));
        }
    }
    Ok(())
}
```

```rust
/// Build the entry for one absolute `path`, wherever it lives. A path that
/// does not exist (or cannot be inspected) is `IconKind::Broken` with mode 0;
/// a symlink is `Symlink` when its target resolves and `Broken` when it
/// dangles. The name is the final path component. `left_out` is `false`.
pub fn entry_for_path(path: &Path) -> IconEntry {
    use std::os::unix::fs::MetadataExt;

    let name = path
        .file_name()
        .map(|n| n.to_string_lossy().into_owned())
        .unwrap_or_else(|| path.display().to_string());
    let (kind, mode) = match std::fs::symlink_metadata(path) {
        Err(_) => (IconKind::Broken, 0),
        Ok(m) if m.file_type().is_symlink() => match std::fs::metadata(path) {
            Ok(target) => (IconKind::Symlink, target.mode()),
            Err(_) => (IconKind::Broken, 0),
        },
        Ok(m) if m.is_dir() => (IconKind::Dir, m.mode()),
        Ok(m) => (IconKind::File, m.mode()),
    };
    let ext = if kind == IconKind::Dir { None } else { IconEntry::ext_of(&name) };
    IconEntry { name, path: path.to_path_buf(), kind, mode, ext, left_out: false }
}
```

```rust
//! Merge the left-out icons (`leftout.json`) into the desktop folder listing.
//! Pure filesystem work, no GTK, so it can run on a worker thread and be
//! unit-tested. See `docs/superpowers/specs/2026-09-30-leaveout-design.md`.

use opusdm_iconview::scan;
use opusdm_iconview::IconEntry;
use opusdm_ipc::LeftOut;
use std::io;
use std::path::Path;

/// Combine the Desktop folder `desktop` entries with the left-out items. A
/// left-out path already listed is flagged in place (it appears once); the
/// others are appended in store order, built with [`scan::entry_for_path`]
/// (so a missing target is an `IconKind::Broken` entry) and flagged.
pub fn merge_entries(mut desktop: Vec<IconEntry>, left: &LeftOut) -> Vec<IconEntry> {
    for item in &left.items {
        if let Some(existing) = desktop.iter_mut().find(|e| e.path == item.path) {
            existing.left_out = true;
            continue;
        }
        let mut entry = scan::entry_for_path(&item.path);
        entry.left_out = true;
        desktop.push(entry);
    }
    desktop
}

/// Read the Desktop folder `dir` (hidden files skipped) and merge in `left`.
pub fn read_desktop_entries(dir: &Path, left: &LeftOut) -> io::Result<Vec<IconEntry>> {
    Ok(merge_entries(scan::read_entries(dir, false)?, left))
}
```

```rust
/// Run a `LeaveOut` or (with `put_away`) `PutAway` step on the SOURCE
/// selection. The selection must not be empty; leaving out also requires
/// every path to be absolute and present. Nothing is emitted on failure.
fn run_leave_out(
    run_id: u64,
    step_idx: usize,
    put_away: bool,
    source: &SelectionCtx,
    events_tx: &Sender<(u64, FnEvent)>,
) -> Result<(), String> {
    let label = if put_away { "Put Away" } else { "Leave Out" };
    if source.paths.is_empty() {
        return Err(format!("{label}: nothing selected"));
    }
    if !put_away {
        opusdm_ipc::leftout::check_leavable(&source.paths)?;
    }
    let paths = source.paths.clone();
    let _ = events_tx.send((run_id, FnEvent::Output { step_idx, line: format!("{label} {} item(s)", paths.len()) }));
    let event = if put_away { FnEvent::PutAway { paths } } else { FnEvent::LeaveOut { paths } };
    let _ = events_tx.send((run_id, event));
    let _ = events_tx.send((run_id, FnEvent::StepDone { step_idx, exit_code: Some(0) }));
    Ok(())
}
```

```rust
/// Read `dir` into desktop entries, merged with the left-out icons in `left`,
/// on a background thread and invoke `on_done` with the result back on the
/// GTK main loop, so scanning a large or slow desktop directory (or stat-ing
/// a left-out target on a slow disk) never freezes the desktop and panel.
fn read_entries_async(
    dir: PathBuf,
    left: opusdm_ipc::LeftOut,
    on_done: impl Fn(std::io::Result<Vec<opusdm_iconview::IconEntry>>) + 'static,
) {
    let (tx, rx) = async_channel::bounded(1);
    std::thread::spawn(move || {
        let _ = tx.send_blocking(opusdm_hub::leftout::read_desktop_entries(&dir, &left));
    });
    glib::spawn_future_local(async move {
        if let Ok(result) = rx.recv().await {
            on_done(result);
        }
    });
}

/// Show `entries` in `field`, first handing it the saved positions of the
/// left-out icons so they land where the user dragged them.
fn show_entries(field: &opusdm_iconview::IconField, left: &opusdm_ipc::LeftOut, entries: &[opusdm_iconview::IconEntry]) {
    field.set_pinned_positions(left.positions());
    field.set_entries(entries);
}

/// Re-read the desktop directory and refresh the icon field with the current
/// left-out store merged in. Does nothing without a field or directory.
fn reload_desktop_field(widgets: &Rc<Widgets>) {
    let field = widgets.desktop.field.borrow().clone();
    let dir = widgets.desktop.dir.borrow().clone();
    let (Some(field), Some(dir)) = (field, dir) else { return };
    let left = widgets.desktop.leftout.borrow().clone();
    read_entries_async(dir.clone(), left.clone(), move |result| match result {
        Ok(entries) => show_entries(&field, &left, &entries),
        Err(e) => opusdm_ipc::err_log!("hub", "cannot read desktop {}: {e}", dir.display()),
    });
}

/// Persist the left-out store, logging (not failing) on error: the in-memory
/// state stays valid and the next change tries again.
fn save_leftout(left: &opusdm_ipc::LeftOut) {
    if let Err(e) = left.save() {
        opusdm_ipc::err_log!("hub", "cannot save {}: {e}", opusdm_ipc::leftout::leftout_path().display());
    }
}
```

```markdown
### 3.21 Leave Out (icons on the desktop)

Any file or folder can sit on the desktop as a permanent icon with a small arrow badge, wherever it really lives:
- Right-click it in a lister and choose **Leave Out on Desktop**. If the clicked entry is part of the selection, the whole selection is left out.
- Or use the **Leave Out** and **Put Away** steps of the Function Editor on the SOURCE selection, so they can be bound to a hotkey.
- **Put Away** is also in the context menu of a left-out icon on the desktop. It only removes the icon; the file is never touched.

Drag a left-out icon to place it: the position is remembered across restarts (icons of the Desktop folder itself are still auto-arranged). A left-out entry whose file disappeared (deleted, or its disk not mounted) stays as a broken icon until you put it away. Double click opens a folder in a new lister and a file with its default application. Left-out icons appear on the primary monitor only. Stored in `~/.config/opusdm/leftout.json`.
```
